# Imputation review: five corrections (2026-10-21)

1. Cell scope is supplied to the imputation engine as target row indices. All counts, missing-after values, cell provenance and after-distributions now describe actual writes. Existing history with complete cell audit is reconciled without rewriting data/revisions; unreliable historical after-distributions are omitted with an explicit note.
2. Surviving imputation/placeholder provenance is reconstructed from actual changes. These cells are excluded from donor observations for later mean/median/mode/directional/interpolation operations. Formatting/renames retain this status, explicit manual corrections clear it, and undo reconstructs it from surviving history.
3. Interactive date median now explains that it estimates a chronological midpoint, not a verified event date. The UI requires acknowledgement before Apply; the same notice is shared by column cleaning settings. Automatic cleaning continues to avoid estimating dates. Estimated dates stay marked and audited.
4. Grouped imputation evaluates only groups containing targeted missing cells. A failed group remains unchanged with its original column/row error and a group-specific warning; valid groups can complete. If all targeted groups fail, the operation returns an actionable error. Missing group keys remain unfilled. Per-cell date format provenance supports independently formatted groups.
5. Date-only midpoint rounding is selectable: floor, nearest (noon rounds upward), or ceil. The policy is included in saved parameters/audit. Timestamp values retain their time. Previously observed values are preserved.

Validation: 258 backend tests; production frontend build/TypeScript; live HTTP smoke via the running frontend proxy covering cell audit, exclusion of prior estimates, both rounding directions, failed-group isolation, undo and CSV/PDF exports. Browser and native UI tools failed to initialize (kernel asset path error), so visual UI verification remains unperformed; no screenshot was fabricated.
